# Статус переработки архитектуры

Обновлено: 2 октября 2026 г.

Актуальная сводка проекта и блокирующие перед выпуском задачи собраны в
[`progress.md`](./progress.md); этот файл сохраняет подробный журнал
итераций.

Документ фиксирует выполненные этапы и оставшиеся задачи по плану новой
архитектуры фронтенда. Миграция продолжается. Визуальный редизайн не входит в
объём работ: при дальнейшей переработке нужно сохранять существующие
оформление и поведение, меняя их только при отдельном согласовании.

## Что уже сделано

### Архитектура и навигация

- Созданы основные каталоги и границы ответственности: `app`, `api`,
  `components`, `features`, `hooks`, `lib`, `store`, `styles` и `utils`.
- Навигация работает через `HashRouter`, чтобы клиентские URL работали на
  статическом хостинге без настройки SPA rewrite.
- Добавлены разбор путей и URL-состояние для экранов событий и связанных
  модальных представлений; подключена интеграция с MAX BackButton и start
  parameters.
- Экраны загружаются отложенно там, где это уже поддержано текущей схемой
  приложения.
- Добавлен `src/pages/TabPages.jsx`: выбор и композиция содержимого вкладок
  вынесены из `components` в `pages`; страницы функций по-прежнему загружаются
  лениво. URL-маршрутизация модальных экранов остаётся в `App` и требует
  дальнейшего выделения.

### API и аутентификация

- Создан общий Axios-клиент; ресурсные запросы распределены по модулям в
  `src/api/`.
- Клиент передаёт MAX `initData` через общий API-слой.
- Сервер проверяет подписанные MAX-данные для защищённых операций и получает
  идентификатор пользователя из проверенной сессии, а не доверяет переданному
  клиентом `userId`.
- Добавлен маршрут собственного профиля `/api/users/me`; операции событий,
  друзей, загрузки файлов, жалоб, геоданных и туристических планов используют
  разделённые API-модули.
- Удалены устаревшие mock-операции друзей; поиск друзей поддерживает отмену
  устаревших запросов.

### Состояние приложения

- Созданы `UiStore`, `SessionStore`, `FiltersStore`, `EventsStore`,
  `FriendsStore` и `TouristStore`, объединённые через `RootStore` и
  `StoreProvider`.
- Основные данные приложения и часть интерфейсного состояния перенесены из
  локального состояния компонентов в stores.
- `EventsStore` нормализует события по идентификаторам, защищает от применения
  устаревших ответов и поддерживает операции участия с откатом состояния при
  ошибке.
- Сессионные, маршрутные эффекты и часть действий профиля вынесены в hooks.
- В локальном dev-клиенте без MAX `initData` автоматически включается гостевой
  просмотр; `?guest=1` и ручное включение также поддерживаются. Серверные
  операции, требующие авторизации MAX, остаются защищёнными.

### Декомпозиция экранов и компонентов

- Страницы друзей разделены на меньшие представления; устранены некоторые
  повторные загрузки после операций.
- Туристический экран разделён на форму, выбор мест, временную шкалу и чистую
  модель маршрута; для модели добавлены unit-тесты.
- Профиль разделён на редактор и `ProfileOverview`; соответствующие стили
  сводной секции вынесены в отдельный CSS Module.
- `App.jsx` теперь отвечает за композицию: действия, lifecycle-эффекты и
  модель отображения вынесены в отдельные hooks; сам файл сокращён примерно
  до 100 строк.
- В текущем этапе адресный поиск и выбор точки на карте вынесены из
  `CreateEventForm.jsx` в `EventLocationFields.jsx` и
  `useEventLocationEditor.js`; поля формы разделены на компоненты, правила
  payload и фотографии имеют отдельные модули. Карта разделена на композицию,
  маркеры и слой туристического маршрута. Контракты и CSS-классы сохранены.

### Стили и документация

- Добавлены CSS-токены в `src/styles/tokens.css` и справочник [`tokens.md`](./tokens.md).
- Для части экранов и компонентов уже используются CSS Modules.
- `Readme.md` обновлён: удалена устаревшая документация `VITE_USE_MOCK`,
  описаны актуальные каталоги и отмечено, что миграция ещё не завершена.
- Изменения цветовой палитры и иные начатые изменения дизайна отменены по
  просьбе пользователя; дальнейшая работа не должна включать редизайн.
