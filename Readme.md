# Вместе — события и досуг рядом

**Вместе** — MAX Mini App и API для поиска городских событий, создания встреч и записи на них. Пользователь выбирает город, находит подходящую активность и может присоединиться; организатор публикует событие, место, время, стоимость и условия участия.

> **Фокус MVP:** путь жителя города «найти подходящее событие рядом → понять условия → присоединиться». Туристический планировщик, социальные функции и отзывы дополняют MVP, но не заменяют этот основной сценарий.
>
> Актуальность проблемы и востребованность решения должны подтверждаться исследованием целевых пользователей. Наличие функций в MVP само по себе не доказывает спрос.

## Пользовательский сценарий

1. Пользователь открывает мини-приложение из бота MAX.
2. Выбирает город, категорию, дату и другие фильтры.
3. Открывает карточку события и проверяет время, место, стоимость и описание.
4. Нажимает «Присоединиться» и видит обновлённое состояние участия.
5. При включённых уведомлениях получает напоминание о событии.

Организатор может создать событие, выбрать точку на карте или найденный адрес, задать дату, время, формат, стоимость, вместимость и изображения. Участник может отказаться от участия. Отзывы доступны после завершения события.

## Возможности

- Лента событий и карта с кластеризацией маркеров.
- Фильтры по городу, категории, времени и стоимости, включая «Пушкинскую карту».
- Создание и редактирование событий, адресный поиск, координаты и загрузка изображений.
- Запись на событие, список участников и напоминания.
- Профили организаторов, отзывы, друзья и ссылка для связи в MAX.
- Туристические планы и подбор мест рядом с событиями.
- MAX Bot с командами `/start`, `/my` и `/help`, deep links и уведомлениями.

### Поток данных

```text
MAX / браузер
      │
      ├── Vite/React Mini App
      │       └── HTTP JSON ──► Express API
      │                            ├── SQLite
      │                            ├── локальные файлы изображений
      │                            └── MAX Bot API
      └── MAX Web App Bridge
```

События и профили сохраняются как JSON в SQLite-таблицах `events` и `users`; связи, заявки, отзывы и напоминания хранятся в отдельных таблицах. В новой локальной базе нет автоматически созданных тестовых событий. `server/db/database.js` — оставшийся in-memory/JSON слой; запущенный API использует `server/db/sqliteDatabase.js`. Автоматическую миграцию данных между этими слоями не предполагайте: перед переносом существующих данных нужна отдельная проверка и процедура миграции.

## Docker

Docker-конфигурация в этой версии репозитория не включена: `Dockerfile`, `compose.yaml`, `.dockerignore` и шаблон `.env.example` отсутствуют. Поэтому требование кейса «запуск всех локальных компонентов одной командой через Docker» пока **не выполнено**, а команду `docker compose up --build` запускать нельзя. Перед сдачей добавьте Docker-конфигурацию и проверьте сборку (до 5 минут без учёта загрузки базовых образов). Локальный запуск ниже предназначен для разработки, но не заменяет это требование.

### Локальный запуск без Docker

Требуются Node.js `>=22.13.0` и npm. Сначала установите зависимости и задайте адрес локального API для Vite. Создайте `.env` в корне со следующим содержимым:

```sh
npm ci
```

```dotenv
VITE_API_URL=http://localhost:3001
VITE_USE_MOCK=false
VITE_BOT_USERNAME=t280_hakaton_max_bot
```

В первом терминале запустите Mini App:

```sh
npm run dev
```

Создайте `server/.env` (токен для локального API не требуется):

```dotenv
PORT=3001
WEB_APP_URL=http://localhost:5173
```

Во втором терминале:

```sh
cd server
npm ci
npm start
```

Vite доступен на `http://localhost:5173`, API — на `http://localhost:3001`. Файл `.env` в корне задаёт настройки клиента, `server/.env` — настройки сервера. Эти файлы не должны попадать в Git.

Для остановки нажмите `Ctrl+C` в обоих терминалах. Для повторного запуска выполните `npm run dev` в корне и `npm start` из `server/`; повторно устанавливать зависимости не нужно. Для изоляции тестовых данных задайте серверу `DB_PATH` с абсолютным путём к отдельному SQLite-файлу до запуска API.

Сборка интерфейса:

```sh
npm ci
npm run build
```

`npm run preview` запускает предпросмотр production-сборки Vite. Это не production-сервер API.

## Настройка окружения

Для локального запуска укажите нужные переменные в `.env` в корне (клиент) и `server/.env` (API). Не добавляйте эти файлы и секреты в Git. Без `VITE_API_URL` клиент использует встроенный публичный API URL; без `BOT_TOKEN` бот отключён. Значения переменных:

| Переменная | Где используется | Назначение |
| --- | --- | --- |
| `PORT` | Сервер | Порт Express API; по умолчанию `3001`. |
| `VITE_API_URL` | Mini App | Базовый URL API без завершающего `/`. Локально `http://localhost:3001`; в Mini App укажите публичный HTTPS URL API. |
| `VITE_USE_MOCK` | Mini App | Для локальной проверки API задайте `false`. Если не задано в Vite dev-режиме, запросы друзей могут использовать локальные моки. |
| `VITE_BOT_USERNAME` | Mini App | Имя MAX-бота для deep links; без `@`. |
| `BOT_TOKEN` | Сервер | Секрет токена MAX-бота. Не требуется для запуска API, требуется для бота, авторизации сохранённых туристических планов и уведомлений. |
| `BOT_USERNAME` | Сервер | Имя бота, открывающего Mini App. |
| `WEB_APP_URL` | Сервер/бот | URL развёрнутого Mini App; локально `http://localhost:5173`. |
| `DB_PATH` | Сервер | Путь к SQLite-файлу; по умолчанию `server/db/events.sqlite`. |
| `UPLOAD_DIR` | Сервер | Путь для загруженных изображений; по умолчанию `server/uploads`. |
| `DADATA_TOKEN` | Сервер | Необязательный ключ подсказок городов DaData. Без него остаётся поиск через Nominatim. |
| `AI_API_KEY` | Сервер | Необязательный ключ AI-провайдера для туристического планировщика и рекомендаций. |
| `AI_MODEL` | Сервер | Модель AI-провайдера. Без ключа и модели AI-функции отвечают `503`; основной поиск и запись на события от них не зависят. |
| `AI_API_URL` | Сервер | Необязательный совместимый URL API чата; по умолчанию используется OpenAI-compatible endpoint. |
| `OVERPASS_API_URL` | Сервер | Необязательный URL Overpass API; при отсутствии используются публичные endpoint-ы из кода. |

Порты локальной разработки: `5173/tcp` (Mini App/Vite) и `3001/tcp` (API).

## Внешние сервисы и данные

- **MAX Web App Bridge / Bot API** — запуск внутри MAX, данные запуска и сообщения бота. Для работающего бота нужен токен из защищённого окружения.
- **OpenStreetMap Nominatim** — поиск адресов и обратное геокодирование.
- **OpenStreetMap Overpass API** — поиск мест рядом с точками туристического маршрута.
- **DaData** — дополнительный поиск городов, только при заданном `DADATA_TOKEN`.
- **AI API** — опциональная генерация маршрута и рекомендаций при настройке `AI_API_KEY` и `AI_MODEL`.

События в MVP создаются пользователями приложения. Не заявляйте их каталог как полную официальную афишу: интеграции с источниками мероприятий в этом репозитории нет. Результаты геосервисов зависят от полноты, актуальности, доступности и ограничений соответствующих публичных сервисов. AI-функции могут быть выключены без влияния на основной сценарий.

## Пошаговая проверка локального сценария

1. Запустите приложение и проверьте `GET /health`.
2. Откройте <http://localhost:5173>, перейдите к созданию события.
3. Создайте будущее офлайн-событие с названием, категорией, датой и временем, адресом/координатами и бесплатной стоимостью.
4. Откройте ленту, найдите событие и откройте его карточку.
5. Проверьте дату, время, адрес и стоимость; пройдите запись под отдельным тестовым пользователем.
6. Проверьте изменение числа участников, затем откажитесь от участия.
7. Для API-проверок выполняйте последовательность из [`DATA-API.yaml`](./DATA-API.yaml). В тестовом теле запроса используйте два разных идентификатора пользователей; создатель события не может присоединиться к собственному событию. Это локальные тестовые actor ID, не MAX-учётные записи.

Ожидаемое поведение API для основного цикла: создание события — `201`, чтение — `200`, запись/отказ — `200`, обновление — `200`, удаление будущего события организатором — `204`. Примеры ниже можно выполнять в POSIX shell после запуска API. Создание использует только локальную тестовую базу:

```sh
curl -i http://localhost:3001/health
curl -i http://localhost:3001/api/events
curl -i -X POST http://localhost:3001/api/events \
  -H "Content-Type: application/json" \
  -d '{"title":"Тестовая прогулка","description":"Локальная проверка API","category":"Прогулка","date":"2099-06-01, 12:00","startAt":"2099-06-01T09:00:00.000Z","duration":"1 ч","format":"Офлайн","price":"Бесплатно","address":"Казань, тестовая точка","district":"Казань","city":"Казань","lat":55.796,"lng":49.108,"maxParticipants":10,"organizerId":"demo-organizer"}'
```

Последняя команда создаёт событие, которое намеренно остаётся в локальной БД. Для повторяемых проверок укажите серверу `DB_PATH` с абсолютным путём к отдельной тестовой SQLite-базе. Удаляйте только этот тестовый файл и только после остановки сервера.

## Контракт API

Полный перечень обязательных проверок основного сценария, ролей, параметров и ожидаемых ответов описан в [`DATA-API.yaml`](./DATA-API.yaml). API отвечает JSON, если маршрут не возвращает `204 No Content` или файлы.

Основные группы:

| Группа | Примеры |
| --- | --- |
| Состояние и стартовые данные | `GET /health`, `GET /api/bootstrap` |
| События и участие | `GET/POST /api/events`, `PUT/DELETE /api/events/{id}`, `POST /api/events/{id}/join`, `POST /api/events/{id}/leave` |
| Друзья и профили | `/api/friends`, `/api/users` |
| Отзывы и жалобы | `/api/events/{id}/reviews`, `POST /api/reports` |
| Геопоиск и модерация | `/api/cities`, `POST /api/moderation/check` |
| Туристические планы | `/api/tourist/*` |
| Изображения | `POST /api/upload` |

### Важное ограничение авторизации API

MAX `initData` с криптографической проверкой используется сервером для сохранения, загрузки и удаления туристических планов. В большинстве остальных API-маршрутов идентификатор пользователя сейчас передаётся в `userId`, `organizerId`, `fromId` или `reporterId`; универсальной серверной проверки подписи MAX для этих операций в текущей версии нет. Такие идентификаторы нельзя считать подтверждением личности. Не используйте текущую конфигурацию как безопасный публичный сервис для персональных или финансовых данных без внедрения и проверки авторизации на всех защищённых операциях.

## Ограничения MVP

- В новой базе нет демонстрационных событий; для проверки их нужно создать.
- Полнота ленты зависит от событий, опубликованных пользователями; официального агрегатора афиш нет.
- Геокодинг, карта, пешие маршруты и места рядом требуют сетевого доступа и ограничены доступностью внешних сервисов.
- DaData и AI-интеграции необязательны; без конфигурации соответствующие функции недоступны.
- Бот и уведомления требуют действительного `BOT_TOKEN` и настройки приложения в MAX.
- Сохранённые туристические планы защищены MAX initData; остальные маршруты в текущем MVP не используют универсальную аутентификацию.
- Веб-сборка сама по себе не регистрирует Mini App в MAX и не заменяет публичный HTTPS-деплой.
