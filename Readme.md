# Вместе

**Вместе** — мини-приложение MAX для поиска городских событий и встреч. Пользователи могут находить активности рядом, знакомиться с условиями участия и присоединяться к событиям. Организаторы — публиковать встречи и управлять ими.

Основной сценарий — найти событие в своём городе, проверить дату, место и условия, а затем записаться. Дополнительные социальные и туристические функции расширяют этот сценарий.

## Как пользоваться приложением

### Участнику

1. Откройте бота MAX и запустите мини-приложение.
2. Выберите город и при необходимости настройте фильтры по категории, дате или стоимости.
3. Откройте карточку события и ознакомьтесь с описанием, временем, местом и условиями.
4. Нажмите кнопку участия; после записи событие появится в списке ваших активностей.
5. Если планы изменились, отмените участие на странице события.

### Организатору

1. Создайте событие и заполните название, описание, категорию, дату и время.
2. Укажите формат, стоимость, вместимость и место проведения.
3. При необходимости выберите точку на карте и добавьте изображения.
4. Опубликуйте событие, следите за списком участников и обновляйте данные при необходимости.

Доступность отдельных возможностей — например, напоминаний, сохранения туристического плана и AI-рекомендаций — зависит от настроек сервера и интеграций.

## Возможности

- **Поиск событий:** лента, поиск и фильтры по городу, категории, времени и стоимости, в том числе по событиям с «Пушкинской картой».
- **Карта и адреса:** просмотр мест проведения, выбор точки на карте, поиск адреса и обратное геокодирование.
- **Управление событиями:** создание, редактирование и удаление событий, вместимость, стоимость и загрузка изображений.
- **Участие:** запись и отказ от участия, список участников и напоминания через MAX-бота.
- **Социальные функции:** профили пользователей и организаторов, друзья, отзывы после события и жалобы.
- **Туристические планы:** построение плана вокруг выбранных событий, поиск мест поблизости и рекомендации при настроенном AI-провайдере.
- **MAX-бот:** команды `/start`, `/my` и `/help`, кнопки запуска Mini App, deep links и уведомления.

## Технологии

| Часть проекта | Технологии |
| --- | --- |
| Мини-приложение | React 18, Vite 5, JavaScript |
| Карты | Leaflet, React Leaflet, кластеризация маркеров |
| API и бот | Node.js 22.13+, Express 4, `@maxhub/max-bot-api` |
| Хранение данных | SQLite через встроенный `node:sqlite`; JSON-поля для событий и профилей |
| Загрузка изображений | Multer; файлы хранятся отдельно от SQLite |
| Интеграция с MAX | MAX Web App Bridge и Bot API |

```text
MAX / браузер
    ├── React Mini App ── HTTP/JSON ── Express API
    │                                    ├── SQLite
    │                                    ├── загруженные изображения
    │                                    └── MAX Bot API
    └── MAX Web App Bridge
```

Vite обслуживает клиент во время разработки и собирает его в статические файлы для публикации. Express API — отдельный процесс: он обслуживает HTTP-запросы Mini App, обращается к базе SQLite, раздаёт загруженные изображения и при настройке взаимодействует с MAX Bot API.

События и профили хранятся в SQLite в таблицах `events` и `users`; связи, заявки, отзывы, жалобы, туристические планы и напоминания используют отдельные таблицы. При первом запуске пустой базы демонстрационные события автоматически не создаются. Рабочий API подключает SQLite-реализацию из `server/db/sqliteDatabase.js`; данные из других старых форматов автоматически не мигрируются.

## Локальный запуск

Требуются **Node.js 22.13.0 или новее** и npm.

В проекте два отдельных npm-пакета: клиент в корне и API/бот в `server/`. Зависимости и точные разрешённые версии зафиксированы в `package-lock.json` и `server/package-lock.json`; используйте `npm ci`, чтобы установить версии из lock-файлов.

### 1. Настройте и запустите Mini App

Скопируйте корневой `.env.example` в `.env`:

```dotenv
VITE_API_URL=http://localhost:3001
VITE_USE_MOCK=false
VITE_BOT_USERNAME=t280_hakaton_max_bot
```

Это публичные настройки клиента; не добавляйте в этот файл токены или ключи.

Установите зависимости и запустите клиент из корня репозитория:

```sh
npm ci
npm run dev
```

Vite обычно доступен по адресу <http://localhost:5173>. Если API и клиент запущены на других адресах, обновите `VITE_API_URL` и `WEB_APP_URL`.

### 2. Настройте и запустите сервер

Скопируйте `server/.env.example` в `server/.env`. Для локальной проверки API можно оставить значения секретов пустыми:

```dotenv
PORT=3001
NODE_ENV=development
WEB_APP_URL=http://localhost:5173
BOT_USERNAME=t280_hakaton_max_bot
BOT_TOKEN=
DADATA_TOKEN=
AI_API_KEY=
AI_MODEL=
```

В отдельном терминале, находясь в корне репозитория, выполните:

```sh
npm --prefix server ci
npm --prefix server start
```

API будет доступно по адресу <http://localhost:3001>. Откройте <http://localhost:3001/health> — в ответе должны быть JSON-поля `status`, `bot`, `eventsCount`, `usersCount`, `seeded` и `timestamp`.

Для локальной проверки интерфейса в браузере `BOT_TOKEN` не требуется: API запустится без бота. Чтобы бот и отправка уведомлений заработали, задайте настоящий `BOT_TOKEN` только в локальном `server/.env` или в защищённых настройках хостинга. Не копируйте секрет в README, Git, клиентский `.env` или сообщения об ошибках. Для запуска приложения внутри MAX настройте Mini App у бота и опубликуйте клиент по публичному HTTPS-адресу.

Чтобы завершить работу, нажмите `Ctrl+C` в обоих терминалах. Для повторного запуска используйте `npm run dev` и `npm --prefix server start`; повторно устанавливать зависимости не нужно.

### Изолированная тестовая база

Не запускайте изменяющие данные API-запросы на рабочем сервере. Для ручной проверки создайте отдельную локальную базу и укажите её **до** старта сервера. Например, в PowerShell из корня проекта:

```powershell
$env:DB_PATH = "$PWD\server\db\events-local-test.sqlite"
npm --prefix server start
```

Изображения при такой настройке будут сохраняться в каталоге `uploads` рядом с тестовой базой. Для отдельного каталога файлов задайте `UPLOAD_DIR` до запуска сервера. При закрытии PowerShell-процесса переменная окружения пропадёт; постоянные `.env` и SQLite-файл остаются локальными и не должны попадать в Git.

## Сборка

Соберите production-версию Mini App:

```sh
npm run build
```

Готовые статические файлы появятся в `dist/`. Для локального предпросмотра выполните:

```sh
npm run preview
```

Эта сборка включает только клиентскую часть: API запускается отдельно. Для подключения развёрнутого API укажите его HTTPS-адрес в `VITE_API_URL` перед сборкой.

## Развёртывание

Корневой [`amvera.yml`](./amvera.yml) описывает публикацию клиентской статической сборки: после `npm run build` содержимое `dist/` становится веб-артефактом. Серверная часть — отдельный Node.js-сервис; ей нужны собственные зависимости, переменные окружения, доступный извне HTTPS endpoint и постоянное хранилище данных.

Для связки развёрнутых частей:

1. Опубликуйте Mini App по HTTPS и настройте его как Web App у MAX-бота.
2. Укажите публичный HTTPS-адрес API в `VITE_API_URL` и пересоберите клиент.
3. На сервере задайте `NODE_ENV=production`, `BOT_TOKEN`, `BOT_USERNAME`, `WEB_APP_URL` и конфигурацию постоянного хранилища. Не задавайте `NODE_TLS_REJECT_UNAUTHORIZED=0`.
4. Проверьте `/health`, загрузку ленты и основной сценарий записи на тестовом окружении.

Не считайте Mini App опубликованным только на основании успешного `npm run build`: сборка создаёт файлы, но не публикует их и не настраивает бота. После публикации проверьте мобильный и веб-клиенты в MAX, включая запуск Mini App из бота.

## Настройки окружения

Скопируйте `.env.example` в корне в `.env`, а `server/.env.example` — в `server/.env`. Клиентские переменные задаются в корневом `.env`, серверные — в `server/.env`. Шаблоны содержат только безопасные настройки для локальной разработки и пустые значения секретов.

### Порты и процессы

| Компонент | Локальный адрес | Назначение |
| --- | --- | --- |
| Mini App, Vite dev server | `http://localhost:5173` | Клиент в режиме разработки |
| Mini App, Vite preview | `http://localhost:4173` | Предпросмотр production-сборки |
| Express API | `http://localhost:3001` | HTTP API, health check и файлы `/uploads` |

API не запускается командами Vite и работает отдельным Node.js-процессом. Сейчас локальный запуск требует двух терминалов. Docker Compose и запуск одной командой пока не настроены; Docker-конфигурация находится в работе и будет добавлена отдельно.

| Переменная | Где используется | Назначение |
| --- | --- | --- |
| `VITE_API_URL` | Mini App | Базовый URL API. По умолчанию используется API проекта; для локального запуска задайте `http://localhost:3001`. |
| `VITE_USE_MOCK` | Mini App | Управляет моками функций друзей. В режиме разработки по умолчанию используются моки; задайте `false`, чтобы обращаться к API. |
| `VITE_BOT_USERNAME` | Mini App | Имя MAX-бота для ссылок и кнопок; по умолчанию `t280_hakaton_max_bot`. |
| `PORT` | Сервер | Порт API; по умолчанию `3001`. |
| `BOT_TOKEN` | Сервер | Токен MAX-бота. Нужен для работы бота, напоминаний и защищённых операций с сохранёнными туристическими планами. |
| `BOT_USERNAME` | Сервер | Имя MAX-бота; по умолчанию `t280_hakaton_max_bot`. |
| `WEB_APP_URL` | Сервер | Адрес Mini App для бота; по умолчанию `http://localhost:5173`. |
| `DB_PATH` | Сервер | Путь к файлу SQLite; по умолчанию `server/db/events.sqlite`. |
| `UPLOAD_DIR` | Сервер | Каталог загруженных изображений; по умолчанию `server/uploads` или каталог `uploads` рядом с базой, если задан `DB_PATH`. |
| `DADATA_TOKEN` | Сервер | Необязательный токен DaData для подсказок городов. |
| `AI_API_KEY` | Сервер | Необязательный ключ совместимого с OpenAI API для туристических рекомендаций. |
| `AI_MODEL` | Сервер | Модель, используемая туристическими AI-функциями. |
| `AI_API_URL` | Сервер | URL совместимого API чата. Код использует `https://api.openai.com/v1/chat/completions`, если переменная не задана; шаблон `server/.env.example` настроен на OpenRouter. |
| `OVERPASS_API_URL` | Сервер | Необязательный адрес Overpass API; если не задан, используются публичные сервисы. |
| `NODE_ENV` | Среда выполнения Node.js | Режим запуска, например `development` или `production`. |

`BOT_TOKEN`, `DADATA_TOKEN` и `AI_API_KEY` — секреты. Храните их только в защищённых настройках сервера или в локальном `server/.env`, который исключён из Git. Не вставляйте реальные значения в README, исходный код, клиентский `.env`, тикеты или скриншоты.

Переменные `VITE_*` встраиваются в клиентскую сборку и доступны пользователям приложения: задавайте через них только публичные настройки, например адрес API и имя бота. Файлы `.env` и `server/.env` не добавляйте в Git.

Не устанавливайте `NODE_TLS_REJECT_UNAUTHORIZED=0`: эта настройка отключает проверку TLS-сертификатов в Node.js и делает соединения уязвимыми для перехвата. Исправляйте цепочку сертификатов или конфигурацию доверенных центров сертификации, а не отключайте проверку.

## API

Все маршруты API имеют префикс `/api`, кроме `GET /health`. Актуальная OpenAPI-схема перечисляет маршруты API и форматы основных запросов и ответов. Основные группы:

| Группа | Маршруты | Назначение |
| --- | --- | --- |
| События и участие | `GET/POST /api/events`, `GET/PUT/DELETE /api/events/:id`, `GET /api/events/joined`, `GET /api/events/participated`, `POST /api/events/:id/join`, `POST /api/events/:id/leave`, `GET /api/events/:id/participants` | Лента и карточки событий, история участий, управление событием и участниками |
| Отзывы | `GET/POST /api/events/:id/reviews` | Чтение и публикация отзывов |
| Стартовые данные | `/api/bootstrap` | Профиль и состояние пользователя для запуска Mini App |
| Пользователи | `GET /api/users/:id`, `PATCH /api/users/:id`, `GET /api/users/search` | Чтение и изменение профиля, поиск пользователей |
| Друзья | `GET /api/friends`, `GET /api/friends/status`, `POST /api/friends/request`, `POST /api/friends/accept`, `POST /api/friends/decline`, `DELETE /api/friends/:friendId` | Список друзей и управление заявками |
| Города и адреса | `GET /api/cities/search`, `GET /api/cities/address`, `GET /api/cities/reverse` | Поиск населённых пунктов и геокодирование |
| Загрузка и жалобы | `POST /api/upload`, `GET /api/upload/list`, `POST /api/reports` | Загрузка изображений, список файлов и отправка жалоб |
| Модерация | `POST /api/moderation/check` | Проверка текста перед публикацией |
| Туристические функции | `POST /api/tourist/plan`, `POST /api/tourist/places`, `POST /api/tourist/search-places`, `POST /api/tourist/recommendations`, `GET/PUT/DELETE /api/tourist/plans` | Построение маршрута, поиск мест и сохранение планов |

Точные параметры, схемы данных, примеры ответов и проверки приведены в [`openapi.yaml`](./openapi.yaml) и [`DATA-API.yaml`](./DATA-API.yaml). OpenAPI описывает доступные HTTP-маршруты, включая загрузку изображений, жалобы, профили, дружбу и туристические функции. `DATA-API.yaml` — отдельный набор воспроизводимых проверок основного сценария, а не полный перечень API. Он включает операции, изменяющие данные, и не предназначен для запуска на рабочей базе.

### Быстрая проверка API

При запущенном локальном сервере выполните GET-запросы, которые не изменяют базу:

```sh
curl http://localhost:3001/health
curl http://localhost:3001/api/events
curl http://localhost:3001/api/bootstrap
```

В PowerShell используйте `curl.exe`, чтобы явно вызвать исполняемый файл curl:

```powershell
curl.exe http://localhost:3001/health
curl.exe http://localhost:3001/api/events
curl.exe http://localhost:3001/api/bootstrap
```

Проверки, которые создают или меняют события, профили, заявки и другие данные, запускайте только на локальной базе или специально подготовленном тестовом окружении. Не запускайте изменяющие тесты против production API: там находятся данные реальных пользователей. Сценарии из [`DATA-API.yaml`](./DATA-API.yaml) нужно выполнять последовательно с тестовыми идентификаторами и шагами очистки.

В `DATA-API.yaml` указан публичный HTTPS endpoint приложения. Перед запуском тестов, которые меняют данные, настройте тестовое окружение или замените `api.baseUrl` на локальный URL; не отправляйте эти запросы на сервер с реальными пользователями.

## Внешние сервисы и данные

- **MAX Web App Bridge и Bot API** — работа мини-приложения внутри MAX и функции бота.
- **OpenStreetMap Nominatim** — поиск и геокодирование адресов.
- **OpenStreetMap Overpass API** — поиск мест рядом с точками туристического плана.
- **DaData** — необязательные подсказки городов при наличии `DADATA_TOKEN`.
- **AI API** — необязательные туристические рекомендации при настройке `AI_API_KEY` и `AI_MODEL`.

Работа карт, геопоиска и рекомендаций зависит от доступности внешних сервисов. Без настройки AI-провайдера туристические AI-функции недоступны; основной сценарий событий работает независимо от них.

## Сквозная проверка основного сценария

1. Запустите Mini App и API по локальным инструкциям выше.
2. Проверьте `GET /health` и `GET /api/events`.
3. В браузере на <http://localhost:5173> создайте будущее событие с местом, датой и временем.
4. Найдите событие в ленте, проверьте карточку и попробуйте открыть его на карте.
5. Выполните запись под другим тестовым пользователем и убедитесь, что участник появился в списке.
6. Отмените участие и проверьте, что состояние обновилось.
7. При необходимости выполните соответствующие сценарии из [`DATA-API.yaml`](./DATA-API.yaml), используя изолированную базу.

Для API-сценария основного цикла ожидаются: создание события — `201`, чтение и обновление — `200`, запись/отказ — `200`, удаление будущего события организатором — `204`. Уточняйте конкретные запросы и предусловия в контракте API.

## Фиксация версии для передачи

Перед финальной передачей проверьте рабочее дерево и создайте commit, содержащий именно передаваемую версию проекта. Получите его идентификатор командой:

```sh
git rev-parse HEAD
```

Укажите этот commit в материалах передачи и убедитесь, что архив/репозиторий для проверки соответствует ему. После дедлайна не меняйте переданный исходный код. Пока изменения не закоммичены, `HEAD` не является идентификатором всей текущей рабочей копии.

## Важные ограничения

- События создаются пользователями приложения; интеграции с официальными афишами нет.
- Для большей части API-маршрутов идентификатор пользователя передаётся клиентом и не подтверждается криптографически. Проверка MAX `initData` применяется к операциям с сохранёнными туристическими планами. Не используйте текущий API для персональных или финансовых данных без полноценной авторизации и проверки доступа.
- Публичный `GET /api/events` возвращает вместе с событиями профиль организатора и ID участников. Текущий контракт не гарантирует, что эти данные доступны только участникам мероприятия; до изменения API не обещайте пользователям обратное.
- `GET /api/upload/list` сейчас возвращает список имён файлов и предназначен для отладки. Перед эксплуатацией ограничьте к нему доступ или удалите этот маршрут.
- Экран согласия и документы в интерфейсе остаются проектными: в них есть незаполненные сведения об операторе, а часть заявлений о передаче данных и их удалении не подтверждена текущей реализацией. До публичного использования заполните и проверьте документы и приведите текст согласия в соответствие с фактической обработкой данных.
- SQLite и загруженные изображения хранятся в файловой системе сервера. В развёрнутой среде настройте постоянное хранилище и резервное копирование для обоих типов данных.
- Docker-конфигурация пока не включена в репозиторий; до её добавления проект запускается локально отдельными командами для Mini App и API.
- Данные старой базы, если она есть, автоматически не переносятся в текущую SQLite-базу. Перед переносом подготовьте и проверьте отдельную процедуру миграции.
- AI-рекомендации требуют корректных `AI_API_KEY` и `AI_MODEL`; без них соответствующие запросы недоступны. Они не требуются для поиска и записи на события.
- Роли `organizer`, `participant` и другие в `DATA-API.yaml` обозначают участников тестового сценария, но не являются ролями авторизации сервера. Запросы теста используют синтетические ID.
- Для реальных пользователей нужны проверка личности и прав на API-операциях, согласованные с фактической видимостью профилей, событий и участников.

## Структура проекта

```text
.
├── src/
│   ├── api/                 # Клиентские запросы к API
│   ├── components/          # Экраны и компоненты Mini App
│   ├── data/                # Справочные данные
│   └── utils/               # MAX Bridge, фильтры и вспомогательная логика
├── server/
│   ├── db/                  # SQLite и слой доступа к данным
│   ├── routes/              # Маршруты Express API
│   ├── utils/               # Авторизация MAX, геоданные и планирование
│   ├── bot.js               # MAX-бот
│   └── index.js             # Точка входа API
├── DATA-API.yaml            # Сценарии проверки API
├── openapi.yaml             # OpenAPI-схема
├── .env.example             # Шаблон переменных Mini App
└── package.json             # Зависимости и команды Mini App
```

Шаблон окружения сервера: `server/.env.example`. Файлы `.env` с фактическими локальными настройками не коммитятся.

Проверка завершения события для отзывов находится в `server/utils/eventTime.js`. Она использует абсолютное время `startAt`, а для старых событий без него — сохранённые дату и длительность.
